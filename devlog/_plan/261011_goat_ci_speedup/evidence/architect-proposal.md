# Goat SSH CI acceleration proposal

Scope: read-only architecture review of `packages/ssh/src/tunnel.test.ts`. The CI report is 1221.11 s for 325 cases (`/tmp/goat-ci/ci-test-durations.tsv:1`). The 238 named tunnel rows sum to 1216.388 s; 87 cases lack individual rows, so lane totals below are lower bounds. No test or CI run was performed for this proposal.

- **D1 | Extract three private fixture modules in `packages/ssh/src/`.** Put module-wide constants, fake process/service factories, `makeUploadFixture`, `recordSpans`, `makeProtocolTestSpawner`, `nativeScripts`, and `installArchivePsDouble` in `tunnel.fixture.ts` (`packages/ssh/src/tunnel.test.ts:32-246`). Put `protocolExecutable` and `makeProtocolFixture` in `tunnel.protocol.fixture.ts` (`:3359-3765`). Export only symbols imported by the split tests; keep per-case mutable state inside fixture calls and dependency direction test files -> fixtures -> production `tunnel.ts`. Do not add package exports or barrels: `packages/ssh/package.json:5-25` lists only production paths. **Evidence:** `packages/provider-opencode/src/server/probeResponses.fixture.ts:1-8` is an imported fixture naming precedent; `tunnel.test.ts:190-199` resolves `./tunnel.ts` relative to the helper module, so same-directory placement retains that URL; `packages/ssh/tsconfig.json:2-6` includes `src`. **Alternative:** the map's `*.testSupport.ts` also stays outside Vitest's test-file include, but has no observed naming precedent and does not receive the `*.test.ts` exceptions in `tsconfig.base.json:55-59` or `vite.config.ts:212-219`. **Risk:** moving a helper can expose stricter diagnostics or alter generated script bytes. Preserve script literals exactly and verify typecheck, targeted lint, Knip, and baseline byte assertions (`tunnel.test.ts:249-299`). `knip.jsonc:98-101` includes package entry exports, so unused fixture exports should be removed, not ignored.

- **D2 | Split into ten test files, preserving case registration and skip wrappers.** Adopt the ten file names, source ranges, case counts, and measured lane totals in `/tmp/goat-ci/split-map.md` section E: `core` 116/94.661 s, `runner-switch` 29/88.061 s, then `protocol-compat` 24/126.099 s, `legacy` 20/115.395 s, `refresh` 16/97.986 s, `manager` 5/136.154 s, `replacement` 37/133.796 s, `acquisition` 40/150.910 s, `stop` 15/157.113 s, and `identity` 23/116.213 s. Treat **about 160 measured seconds per file** as the initial lane ceiling, not a wall-time promise. **Evidence:** the original seven `describe` blocks begin at `tunnel.test.ts:248,1035,1591,1857,2818,3050,3356`; protocol selection alone spans `:3356-5467` and has 180 cases/1033.666 matched seconds. `*.test.ts` is included by installed Vitest's default pattern (`node_modules/.pnpm/vitest@5.0.1_*/node_modules/vitest/dist/config.cjs:15`); `packages/ssh/package.json:27-30` runs the directory. **Alternative:** splitting only at top-level blocks leaves the 1034 s protocol bottleneck; splitting every protocol parameter family now increases fixture/import churn for little proven benefit. **Risk:** the first two target files combine noncontiguous ranges, and platform skips at `tunnel.test.ts:1857,3050,3356` must survive intact. After one measured EPYC run, split `protocol-stop` or `protocol-acquisition` further only if an observed file exceeds roughly 180 s or holds the critical path.

- **D3 | Limit CI SSH file concurrency initially to six; retain the current Vitest pool and root config.** Set `VITEST_MAX_WORKERS=6` only on the SSH test invocation in `.github/workflows/goat-ci.yml:65-70` (or an equivalent package-scoped invocation); leave `vite.config.ts:62-79` unchanged. Keep the installed default `threads` pool and isolation until an A/B run demonstrates that `forks` improves wall time or stability. **Evidence:** root config has no worker/pool override (`vite.config.ts:62-79`); installed Vitest resolves to `threads` and reads `VITEST_MAX_WORKERS` (`node_modules/.pnpm/vitest@5.0.1_*/node_modules/vitest/dist/chunks/index.DzobfTyw.js:14507-14518`), while run mode otherwise uses `availableParallelism - 1` (`:11777-11782`). With ten files, uncapped workers could start all ten subprocess-heavy fixtures together. **Alternative:** `maxWorkers` in root config affects web and other packages; an SSH-specific config adds another configuration surface; `forks` may isolate native subprocess behavior better but adds worker startup overhead. **Risk:** six is a starting control, not an optimum. Compare 4/6/8 on the EPYC runner using total SSH wall time, peak child processes/FDs, and failures. CI environment or flags may override effective concurrency; capture the resolved worker count.

- **D4 | Batch the native script-byte test's Node generation.** Extend `nativeScripts` to accept a collection of `{input, selection}` requests and return corresponding results from one native Node import; retain a single-request wrapper for other callers. Change the byte-preservation case to submit its existing 16 requests as one batch and assert each result in the same variant order. **Evidence:** `tunnel.test.ts:190-223` starts one `process.execPath` child per call, and `:251-285` makes 16 calls; that CI case took 11.215 s (`/tmp/goat-ci/ci-test-durations.tsv:21`). The comment at `tunnel.test.ts:189` explains why native module evaluation matters. **Alternative:** caching all script output across tests risks wrong input/selection or hiding a state-related bug; changing production builders is unnecessary for this gain. **Risk:** preserve every baseline assertion and native, untransformed import; make result indexing explicit. The 11.215 s is an upper bound on savings, not measured Node startup cost.

- **D5 | Shorten only the fixture's unowned-lock poll interval with a default-valued builder placeholder.** Add an optional, builder-only poll-seconds argument to `buildRemoteT3RunnerScript` that defaults to `1` and substitutes the `sleep 1` operand, then pass a small value only in the stale-lock test. Keep it out of the runtime `RemoteT3RunnerOptions` contract (`tunnel.ts:77-108`). Preserve the default rendered script byte for byte and its baseline assertion. **Evidence:** the shell waits after each unowned-lock observation at `tunnel.ts:618-640`; the builder maps script placeholders at `:1387-1410`; the test creates an unowned lock at `tunnel.test.ts:1847-1851` and currently calls the default builder at `:1815-1818`. Reclaim happens on the fifth observation _before_ sleeping, so this phase has four guaranteed 1 s sleeps, not five; its total CI duration was 6.360 s (`/tmp/goat-ci/ci-test-durations.tsv:69`). **Alternative:** a test-only fake clock cannot advance real shell `sleep`; changing the shared 1 s default would alter production behavior and bytes. **Risk:** the test would validate five observations rather than four elapsed seconds. Keep another default-byte check and document this limit in the test name/comment if implemented. Do not reduce `REMOTE_REUSE_READY_TIMEOUT_MS` globally (`tunnel.ts:75`).

- **D6 | Defer other wait changes until subprocess timing exists.** Add temporary per-command timing around the fixture transport if a second optimization pass is needed; do not shorten readiness, stop, or force-kill budgets based on the TSV alone. **Evidence:** the protocol fixture starts real `mkfifo`, Node, `tar`, shell, and CLI children (`tunnel.test.ts:3496-3509,3533-3587,3641-3692`); archive `wait-ready` waits on a FIFO event and one HTTP request (`:3413-3424`). Retain the real shell, ownership, rollback, and publication checks.

- **D7 | Keep the four-job CI matrix and sequential SSH/web test job for this change.** Only apply the SSH worker cap in the existing test step; measure end-to-end workflow time before deciding whether web deserves a separate job. **Evidence:** `.github/workflows/goat-ci.yml:18-26` runs `check`, `typecheck`, `test`, and `build` on the EPYC label; `:36-55` repeats setup and Electron installation per job; `:65-75` runs SSH, web, and build-script tests in one test job. **Alternative:** adding an SSH/web matrix job lets web run sooner but adds another checkout/install/setup and competes for the two runner slots; it does not accelerate SSH itself. **Risk:** the test job remains gated by SSH. If SSH falls to a few minutes and web/build-script duration dominates, remeasure the complete workflow before restructuring it.

- **D8 | Gate the implementation on isolation and load evidence.** Keep each test's scoped temp home and captured-process cleanup (`tunnel.test.ts:3486-3494,3513-3528`); do not share writable state across files. Real listeners use ephemeral/dynamically reserved ports (`:3410-3411,3531-3545`), but `reserveLoopbackPort` followed by bind has a race that parallel load could expose. The fake `41773` port is not a listener (`:96-102`). **Alternative:** forcing one worker avoids most load but defeats the split. **Risk/assumptions:** FD/process limits, runner co-tenancy with check/build, filesystem throughput, and actual worker override are unmeasured. Verify 325 registered cases, targeted SSH pass, zero fixture residue, and at least two EPYC timings; inspect any flakes by failure mode rather than adding sleeps. The 160 s lane target assumes the named duration rows represent the expensive cases and that six workers do not materially inflate per-case time.
