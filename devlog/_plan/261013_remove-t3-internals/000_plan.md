# 000 — Remove internal T3 traces (T2 roadmap)

GOAT still carries upstream T3 Code's internal names: the `@t3tools/*` package scope (3,234 files), `T3CODE_*`/`T3_*` env vars (~200 names), `~/.t3` and `.t3` data paths, `t3code:*` storage keys, `t3.json`, `t3-*://` URIs, eight `t3-*` mobile native modules, the `oxlint-plugin-t3code` lint plugin, and many `T3*` identifiers. This unit renames everything GOAT owns to GOAT names. Each name that carries user data or user configuration keeps a fallback or migration. External contracts and attribution stay unchanged.

Bundle: T2 (merges last, after S1 upstream sync and T1 visible branding). Branch `chore/remove-t3-internals-r2` from origin/dev `4ed8d2739`, draft PR #98 until S1 and T1 land.
Research: `001_inventory.md`. Audit record: `002_audit.md`.

## Loop spec

- Archetype: satisfy-spec, multi-cycle. wp1 is this docs-only roadmap; each later work-phase is one PABCD cycle and one or more small commits.
- Goal: no GOAT-owned identifier, package, env var, path, or storage key uses a T3 name, except the phase-2 list (D17) whose readers already accept both spellings. Existing user data and configuration keep working across upgrade and rollback. A rename tool reproduces the mechanical part after every upstream sync.
- Non-goals: user-visible strings, docs prose and comments (T1), `.repos/`, devlog history, upstream-owned disabled workflows, T3 Connect relay vocabulary, upstream attribution and LICENSE files.
- Verifier per cycle: targeted `vp test run` for touched tests, targeted typecheck/lint for touched packages, `node scripts/goat-rename.ts --check`, independent gpt-6.1-sol review. Final: all goat-ci jobs green locally and on the PR.
- Stop: every work-phase done with fresh evidence and S1/T1 merged and rebased, or a blocker needing a human decision.
- Escalation: anything that would rewrite live `~/.goat` or `~/.t3` state, publishing, marking the PR ready before S1/T1 merge.

## Applying the renames on a future upstream sync

1. `git worktree add ../upstream-<tag> <tag>`, then from the dev checkout: `node scripts/goat-rename.ts --apply --root ../upstream-<tag>` and commit there as `chore(rename): [script] upstream <tag>`.
2. Merge that commit into dev instead of the raw tag. Both sides already carry identical renamed lines, so only real conflicts remain.
3. After resolving, rerun `node scripts/goat-rename.ts --apply` (idempotent) and `--check`. A new upstream T3 name either matches a rule or fails `--check`; add a rule, or a keep entry with a reason.
4. A new upstream persisted key, wire id or env var that existing data or older peers depend on also gets an entry in `legacyT3Names.ts` and a dual reader.
5. When a rebase regenerates a script commit, stage with `git add -A -- . ':!.goat' ':!.t3'`. Commits replayed before the `.goat` ignore rule would otherwise pick up a worktree's dev home, secrets included.
