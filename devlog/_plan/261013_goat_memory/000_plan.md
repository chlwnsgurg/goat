# 000 — GOAT cross-device, cross-provider memory (roadmap)

GOAT runs one server per machine and drives six provider harnesses, so anything an agent learns today stays in one machine's provider-specific memory (`~/.codex/memories`, Claude auto memory, omo repos). This unit gives GOAT its own memory: every environment writes user, project and thread memories; a hub environment shares them; forgetting propagates everywhere and beats concurrent edits; a conflict on one memory is quarantined and auto-resolved by the first environment that claims it, with a one-step revert, while every other memory keeps syncing; every provider receives the same bounded snapshot and the same MCP tools; provider-native memories are imported read-only.

Requirements: goat_initiative `devlog/_plan/261013_memory_interview/000_interview.md` (confirmed requirements 1-6; requirement 7: bounded memory storage and index growth, Jun 2026-10-14). Research: goat_initiative `research/075`, `080`, `090`, `100`, `110`, `120`, `130`. Architect proposal: [001_architect_proposal.md](001_architect_proposal.md) (decisions M1-M18; accepted M19 and M20 amendments below). Product design (Korean, for the initiative): goat_initiative `docs/080_memory.md`.

Branch `goat/goat-cross-device-provider-memory` from origin/dev `1e2418faf`. One PR per work-phase, stacked in dependency order (DEV-STACK-01): WP1 -> WP2 -> WP3 -> WP4 -> WP5 -> WP6. WP0 (this roadmap) ships as the first commit of the WP1 PR and as a goat_initiative PR.

## Loop spec

- Archetype: satisfy-spec, multi-cycle HOTL (cxc-loop). WP0 is this docs-only roadmap; each later work-phase is one PABCD cycle and one PR.
- Trigger: Jun asked to build GOAT memory through repeated PABCD and PRs after the 2026-10-13 memory interview.
- Goal: the confirmed requirements 1-7 hold end to end across environments and providers, with M1-M20 implemented as decided below.
- Non-goals: changing Aside memory or aside-memory-sync; writing real `~/.goat`, `~/.t3`, `~/.codex`, `~/.claude` or `~/.omo` state; restarting live servers; pushing to dev or main, merging, releasing; team (multi-owner) sharing; writing back into provider-native memory.
- Verifier per cycle: on this Mac (juns-macbook-pro) only static checks — targeted `vp exec tsc --noEmit -p <package>` (or the package typecheck script) and targeted lint for touched packages — because Jun forbade local test runs on 2026-10-13 (goalplan decision `localtests`). Focused tests are still written for every behavior; they run in PR CI (goat-ci), and the PR CI result for that head is the test evidence. Independent gpt-6.1-sol review per PR. User-visible WP6 surfaces additionally need one integrated client pass, which also runs on CI or another machine, not here.
- Stop: every work-phase has an open PR whose head passed CI and review, and the three-environment scenario tests (WP3) are green in CI; or a blocker that needs Jun.
- Memory artifact: this unit directory and `.codexclaw/goalplans/goat-cxc-loop-hotl-pabcd-pr-goat-environment-thr/` (gitignored).
- Expected terminal outcomes: DONE (all PRs open, CI green, reviews pass); NEEDS_HUMAN (merge, choosing the real hub environment, any real-data run); BLOCKED (same blocker three times); UNSAFE (risk to real user data).
- Escalation: anything that would touch live state, a provider adapter change that cannot be proven without a live provider, CI infrastructure failures that are not ours.
- Resource bounds: none stated by Jun; host limits apply. Tools: gh, vp (typecheck/lint only), sol subagents without limit (Jun, 2026-10-13), Aside exec for web research.
