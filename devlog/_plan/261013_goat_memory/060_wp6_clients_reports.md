## 5. Reports: ownership, safe details and replay

Only approved resolves/reverts and conflict-resolution failures enter the GOAT Bot result channel. Summary/consolidate failures remain Settings processing status only, with zero Bot rows. Classify using body-free outbox resolution_id/operation kind or retained metadata, never bodies or a failed outcome alone; apply the allowlist in SQL before acquireReports LIMIT and before computing dispatch wakeups. Unknown or contradictory classification is not deliverable. No remember/edit/import/sync chatter, manual decision engine, provider task, reception/Slack route, OS notification/sound/push or synthetic run. Terminal generation failure stays a safe failure status/record under existing M11, never an applied resolution. A successful resolution detail shows both originals (all input heads when more than two), judgment, applied result, requested selection/effective provider and model, resolving device and every sourceThread's exact environment/thread reference. Payload is fetched only with live memory:read and local availability; source transcript additionally checks orchestration:read/owner policy. Forget or retention can remove originals/judgment: show unavailable, never invent or regenerate them.
