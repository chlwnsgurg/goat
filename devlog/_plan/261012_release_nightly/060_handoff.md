## Activation

`goat-nightly.yml` listens for completed `goat-ci` runs on `dev`, but GitHub reads `workflow_run` and `workflow_dispatch` definitions only from the default branch, which is `main` (checked 2026-10-12). Merging into `dev` therefore runs nothing. Actions is enabled for goat-si/goat and a newly added workflow starts active, so the first promotion that puts the file on `main` turns it on: from then on every successful goat-ci run of a dev push starts it. If tasks 2–9 and 13 are not done by then, disable it right after that promotion with `gh workflow disable goat-nightly.yml --repo goat-si/goat` and enable it later with `gh workflow enable goat-nightly.yml --repo goat-si/goat`. Optional first manual run: `gh workflow run goat-nightly.yml --repo goat-si/goat --ref main`. Switching the default branch to `dev` is the alternative.

## Bootstrap

The installed 0.0.45 apps have no update feed, so both Macs move to the first nightly by hand once (goat_initiative `docs/050_release_channel.md` §11):

1. Record both Macs' and the SSH hosts' architecture, app path and bundle ID, whether each remote runtime is GOAT-managed, and whether the two Macs use the same remote.
2. Quit both old apps first and turn off their auto-launch and reconnect. 0.0.45 ignores the remote lock and protocol 1001 and may put an incompatible remote runtime back to its own version without checking activity.
3. The bootstrap release is the first nightly that contains wp3 (this branch). Record its version, download its DMG from goat-si/goat-releases, and replace the app on both Macs. Check that user data and saved connections survive.
4. Start both apps. Check `Contents/Resources/app-update.yml`, the bundled runtime, the signature (`codesign --verify --deep --strict`, `spctl -a -vv`) and the version. Watch the remote runtime move to the new version once it is idle.
5. If a remote stays on the old version after its work has finished, GOAT cannot take it over by itself: a server it did not launch (or cannot prove it launched) is left running and the error names its PID, and a 0.0.45 runtime without the activity endpoint stays pending with "waiting for a verified idle response". Check on the host that no agent work is running, stop that process (`kill <PID>` from the error, or the `goat serve` process under `~/.goat/runtime`), then reconnect from one Mac and check the version of the server that is now running (see step 6).
6. Merge a small change into dev. When the next nightly publishes, record both apps' versions and, on each remote, the version of the running server: find its binary with `ps -o command= -p <PID>` (it lives under `~/.goat/runtime/goat/versions/<version>/` and is not on PATH) and run that path with `--version`; all equal without manual steps is the completion evidence for the release channel.

## Measurements

- M1 (keychain session): a gui-domain LaunchAgent (what `svc.sh` installs) sees the login keychain unlocked and reaches notarytool profiles; a Background session (SSH, LaunchDaemon) gets "User interaction is not allowed". FileVault is on, so an unplanned reboot needs a console unlock (which also logs in the user). Evidence: `evidence/m1_keychain_session.txt`, `evidence/m1b_preflight_sessions.txt`.
- M3 (Intel DMG on arm64): unsigned x64 DMG/ZIP build in 52 s; 30 of 31 Mach-O files carry x86_64 (the other is objc-js's unused arm64 prebuild); codesign signs x86_64 binaries here; nothing x64 runs without Rosetta. Evidence: `evidence/m3_x64_cross_build.md`.
- Dry run: arm64/x64 builds with builder payload reports, real darwin-arm64 CLI archive + smoke test + payload scan, assemble with SHA256SUMS, publish/prune plans against goat-releases (read-only). Unsigned DMGs are refused by assemble. Evidence: `evidence/dryrun_r3_chain.txt`, `evidence/m4_install_runner_dryrun_aqua.txt`.

## Remaining risks

- No real Developer ID signature, notarization, stapling or Gatekeeper assessment has run; the first macOS job is the first proof (fails closed if anything is missing).
- Windows, Linux arm64 and EPYC jobs have never executed; hosted runner availability (`windows-11-arm`) and costs are unmeasured.
- The Mac runner boundary depends on the advisory guard on the free plan (task 9). The guard pins prepare's resolve step by hash: editing that step requires updating the pin in .vite-hooks/goat-workflow-guard.mjs, and any expression string mentioning "secrets" outside publish is refused.
- Idle detection: a race remains between the last idle probe and stopping a backend or remote runtime; WSL backends always postpone automatic restart; legacy runtimes without the activity endpoint stay pending.
- A crashed recovery lock on a remote needs manual removal (the UI says which path).
- The SEA path rewrite relies on the checkout root appearing verbatim; the payload scan fails the build if any machine path survives.
- Pre-existing failures unrelated to this work, identical on origin/dev: `.github/scripts/*.test.cjs`, `apps/server/scripts/migrate-dev-db.test.ts`, two `apps/mobile/scripts` tests.
