## Facts that shape the plan

- **Builder already supports the D-3/D-4 credentials.** electron-builder 26.15.6 takes the keychain from `CSC_KEYCHAIN` (`app-builder-lib/out/macPackager.js:49`) and notarizes with `APPLE_KEYCHAIN_PROFILE`/`APPLE_KEYCHAIN` (`app-builder-lib/out/mac/MacTargetHelper.js:245`) through @electron/notarize 2.5.0 (`notarytool.js:75`, requires status Accepted at `:147`, staples via `index.js:47`). API-key and Apple-ID env win over the profile (`MacTargetHelper.js:224,239`) and missing credentials only warn (`:263`). Hardened runtime is on by default (`:177`).
- **Our build disables signing unless told.** `build-desktop-artifact.ts:4301-4307` scrubs CSC/Apple env for unsigned builds; signed builds use `scripts/sign-macos.ts` (osx-sign, batched). The update feed is emitted only when `T3CODE_DESKTOP_UPDATE_FEED_ENABLED=true` and `T3CODE_DESKTOP_UPDATE_REPOSITORY` equals the constant at `:65` (`:2757-2776`).
- **CLI notarization is API-key only and partial.** `build-cli-archive.ts:285-290` reads `APPLE_API_KEY*`; `:341-345` warns and returns without them; `:351` zips only the main executable for submission, so signed helpers/addons are never submitted.
- **x64 macOS desktop has a source path on arm64 hosts.** Target architecture flows through pnpm `supportedArchitectures` (`build-desktop-artifact.ts:1667`), node-pty ships both Darwin prebuilds (`:1058`), Rust helpers cross-compile to `x86_64-apple-darwin` (`:148,:2427`), SQLite is `node:sqlite`. No darwin-x64 SSH runtime is bundled (`:3132`), consistent with D-7.
- **Updater.** `DesktopUpdates.ts:933-934` keeps autoDownload/autoInstallOnAppQuit off; nightly allows downgrades (`:394-398`); install stops every pooled backend then `quitAndInstall(isSilent, isForceRunAfter)` (`:629-646`). Nightly regex already accepts `0.1.0-nightly.YYYYMMDD.N` (`updateChannels.ts:3`). Idle signal: `GET /.well-known/t3/activity` (loopback only, `apps/server/src/http.ts:325-334`; busy definition `ProjectionStore.ts:5951`).
- **SSH replacement.** Supply order: live/retained → installed → bundle → cache → explicit mirror → gh (`tunnel.ts:1794-1870`). Only the "older compatible" path checks activity (`:779`, recheck `:1187`); legacy takeover (`:748,:758`) and owned-incompatible replacement (`:784-787`) do not. The first-connect decision is consumed after any successful ensure, including busy reuse (`:2893,:2919`), so a busy runtime is never retried. The only lock is in-process (`:2519-2527`). Equal/newer compatible runtimes are already kept (`:1784`), but legacy/incompatible paths have no downgrade refusal.
- **Protocol constants** are consumed through the exported names in production; tests/fixtures hard-code `1`/`2`/`"orchestrationProtocol=2"` at the anchors listed in the L2 report. `environmentHttp.ts:83` already uses `ORCHESTRATION_PROTOCOL_VERSION_TEXT`.
- **Repository facts.** goat-si/goat is PRIVATE with default branch **main**; every workflow except goat-ci.yml is `disabled_manually`; ten EPYC runners `[self-hosted, Linux, X64, goat, epyc]` are online; no macOS runner. goat-si/goat-releases exists (public, main `0caa0cf`).

## Measurements on this Mac (juns-mac-studio, Mac16,9 M4 Max, macOS 26.6.2)

**M1 — keychain access by session type.** A temporary LaunchAgent `dev.goat.keychainprobe` was bootstrapped into `gui/501`, kick-started once and booted out (no persistent change; probe script under `~/.cache/goat-probe`). Output (`evidence/m1_keychain_session.txt`):

| Session                                              | `launchctl managername` | `security show-keychain-info login.keychain-db` | `notarytool history --keychain-profile <missing>`            |
| ---------------------------------------------------- | ----------------------- | ----------------------------------------------- | ------------------------------------------------------------ |
| gui/501 LaunchAgent (what `svc.sh install` creates)  | Aqua                    | `no-timeout`, rc 0 (unlocked)                   | "No Keychain password item found for profile" (lookup works) |
| This agent's shell (same as SSH / LaunchDaemon-like) | Background              | "User interaction is not allowed"               | —                                                            |

Conclusion: the runner must be a gui-domain LaunchAgent, and it works only while user `jun` is logged in at the console. FileVault is **on**, so auto-login is impossible and an unplanned reboot needs a person at the FileVault prompt anyway (which also logs that user in). Planned restarts use `sudo fdesetup authrestart`. The juns-macbook-pro finding in 050 §5 (unlock and sign in the same session) matches the Background row.

Not yet measurable here, because the identity is not installed: whether `codesign` can use the private key without a UI prompt. That depends on the key's partition list, set when the user imports the identity (`security set-key-partition-list -S apple-tool:,apple:,codesign: -s ...`). It becomes a runner preflight step (`codesign` on a scratch binary) and a user task.
