# 000 — GOAT nightly release channel, stage 2 (roadmap)

Merging to `dev` should end with both Macs' GOAT apps and their SSH runtimes on the same new nightly without a human. Today nothing is published: goat-si/goat is private, has no releases, and the update feed is off. This unit implements stages 1–3 of the release-channel design (goat_initiative `docs/050_release_channel.md`, decisions D-1..D-12 in its §1 "확정" block) in this repository and prepares, without executing, everything that needs a human or external state.

Source worktree: `/Users/jun/.goat/worktrees/goat/goat-release-nightly` (branch `goat/release-nightly`, base `origin/dev` `32f7bda9b`, which already contains the vp lookup fix `bb3703b35`).
Research: `001_research.md` (three gpt-6.1-sol read-only lanes + measurements on this Mac).

## Loop spec

- Archetype: satisfy-spec, multi-cycle HOTL. wp0 docs-only roadmap, then one PABCD per work-phase.
- Goal: dev merge → goat-ci success → `goat-nightly.yml` builds, signs, verifies and publishes `0.1.0-nightly.YYYYMMDD.N` to goat-si/goat-releases → apps auto-update when idle → SSH runtimes converge when idle.
- Non-goals: stage 4 hardening, latest channel, npm/AUR/relay/Vercel/mobile EAS, Windows signing, darwin-x64 CLI (D-7), any external state change (see "Boundary").
- Verifier per cycle: `vp test run <touched tests>`, targeted `tsc --noEmit` per touched package, `vp lint` on touched files, `actionlint` for workflows, an unsigned local dry run in wp4, and an independent review from a different model family than the builder.
- Terminal outcomes: DONE (all criteria met, branch pushed), NEEDS_HUMAN (only external actions remain — expected for activation), BLOCKED, UNSAFE (secret handling required). Budget: none stated; host limits apply.
- Resources: local shell, gh (lidge-jun, read-only use), gpt-6.1-sol subagents (user grant, unlimited). Write scope: this worktree and this unit. Push scope: `origin goat/release-nightly` only.

## Boundary (from the user brief)

No PR, tag, release, dev merge, goat-releases write, GitHub App, secret, runner registration, workflow enable/run, keychain change, or notarytool credential storage. Do not touch the running GOAT app (127.0.0.1:3773), its SSH runtimes, or the other worktree. Never read, print or move secret values. Every such action goes to the user task list in the wp4 record with exact commands.

Orchestrator update (2026-10-12): goat-si/goat-releases now exists (public, `main` `0caa0cf`, README.md + NOTICE.md, deliberately no LICENSE). The publish script owns syncing `install.sh`, `install.ps1` and `THIRD_PARTY_NOTICES` there.
