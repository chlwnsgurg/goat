# 020 — 070 봇 화면 완성 (wp2)

계약 기준으로 만든다. dev의 `WsRpcGroup`에는 channel RPC가 없고(#32가 서버 핸들러·스코프와 함께 넣는다) 그래서 dev에서 `createEnvironmentRpcCommand({tag: "channel.ensureBot"})`는 타입 오류다. 화면은 주입 포트(`GoatBotChannelPort`: ensureBot, ingest, listTasks)를 받고, dev에서는 포트가 비어 있어 "지원하지 않음"으로 남는다. wp4에서 #32의 `channelEnvironment`로 포트를 채운다.

## 받아들임 기준 (활성화 시나리오)

모두 jsdom(createRoot/act, GoatBotComposer.test.tsx 방식) 또는 순수 함수다. 주입 포트(GoatBotChannelPort)에 가짜 구현을 넣고 실제 컨트롤러(useGoatBotSession + 큐 + GoatBotChatView)를 마운트한다.

1. 두 번째 전송: 첫 ingest가 receipt로 끝난 뒤 running 칩 행이 남아 있고 답이 오지 않은 상태에서 두 번째 메시지를 입력·전송하면 ingest가 두 번, 서로 다른 idempotencyKey로 불리고 입력창은 내내 활성이다. 첫 ingest가 끝나기 전 두 번째 submit은 첫 결과 뒤 순서대로 나간다.
2. 칩 링크: 메모리 라우터에서 worker가 있는 running 칩의 "Open thread"를 누르면 경로가 /$environmentId/$threadId로 바뀌고 ThreadRouteView가 그 스레드를 ChatView 분기로 고른다(봇 분기 아님). received 칩은 비활성 버튼. 무거우면 라우터 이동까지만 확인하고 ChatView 분기는 isGoatBotThread 순수 테스트로 대신하며 C에 기록한다.
3. 미지원: channelLedger 없는 환경이면 안내가 보이고, 입력 이벤트가 ingest를 부르지 않는다.
4. 연결 끊김: 행이 있거나 없거나 offline이면 머리 아래 띠, 입력창 비활성, 기존 행 유지. 다시 연결(세대 변경)되면 ensure가 한 번 다시 불리고, 새 detail 항목이 들어오면 행이 채워진다.
5. ensure 공유와 무효화: /bot과 스레드 화면이 같은 환경·세대에서 ensure를 한 번만 부른다. 세대나 capability가 바뀌면 진행 중 응답은 버려진다(기존 goatBotEnsure 테스트 확장). legacy_active 뒤 legacy 스레드가 실행→정지로 바뀌면 한 번 다시 ensure.
6. 재시도와 정합: 실패한 메시지 Retry는 같은 idempotencyKey로 ingest한다. projection 항목(inputId)이 RPC 응답보다 먼저 와도 말풍선이 두 번 보이지 않는다.
7. 답 연결: 입력 A, B 뒤 B의 답이 먼저, A의 답이 나중에 오면 A의 답에 A 인용, B의 답에는 인용 없음. 순서는 서버 순서 그대로.
8. 읽음: readAt이 있으면 "Read"와 readAt 시각, 없으면 "Sent".
9. 칩 대상 환경 상태: 대상 환경이 연결 안 됨이면 "Can't reach the work computer", 그 환경 bootstrap이 끝났는데 shell이 없거나 지워졌으면 "Work history not found", bootstrap 전이면 비활성 로딩. 요약은 남는다.
10. 배지: waiting_input 작업 101개(두 페이지)를 101로 센다. 오류 회차는 이전 값 유지, 처음부터 오류면 배지를 숨긴다.
11. 접수 실패: kind failure 메시지는 실패 말풍선(기존 reader 테스트).
12. legacy_active: ensure가 legacy_active면 "끝나면 GOAT 봇으로 바뀐다" 안내와 기존 global agent 링크, 입력창 비활성. legacy 스레드가 실행→정지로 바뀌면 ensure 한 번 재시도(5와 같은 테스트 파일).
13. 빈 화면: ready이고 행이 없으면 소개 한 줄과 예시 2~3개가 보인다.
14. 로고: 봇을 지원하는 환경이 있으면 로고 대상이 /bot·"Open GOAT Bot", 없으면 기존 global agent(순수 함수).

## 범위 밖

작업자 ChatView 변경 없음. 첨부 전송 없음(070 첫 범위는 텍스트). 모바일은 봇 스레드를 일반 메시지로 읽는다(L2b가 runless 메시지로 기록하므로 변경 불필요, 070 "검증과 모바일"). 데스크톱은 웹을 감싸므로 따로 바꿀 것이 없다. 커맨드 팔레트와 키 바인딩에는 global agent를 여는 항목이 없어(dev 확인) 바꿀 것이 없다.

의도한 예외: 저장된 botRef가 가리키는 스레드는 서버 capability가 없어도 봇 화면으로 연다(코딩 컴포저가 봇 스레드에 나타나지 않게). 전송은 capability와 이번 연결의 ensure 확인이 있어야 열린다.
