# Repo hygiene: leftover T3 names and root dot-folders

Branch `chore/repo-hygiene-t3-dotfolders` from origin/dev `f045007ed`. Follows
[261013_remove-t3-internals](261013_remove-t3-internals/000_plan.md) (D1–D17), which already
decided most T3 names. This pass covers what that plan left open: the repository's own skill
names, its project file, the root dot-folders, and stray tracked files.

Rule used throughout: an upstream-shared path that GOAT renames or drops gets a rule in
`scripts/lib/goat-rename/rules.ts`, so the next chase reproduces it with
`node scripts/goat-rename.ts --apply` instead of a hand-resolved conflict. A new drop rule kind
(`DROP_RULES`) does for deletions what path rules do for moves; `--check` reports a dropped path
that a merge brought back.

## Compatibility

- Project file: GOAT reads `goat.json` first and falls back to `t3.json`; user repositories are unaffected. A maintainer on a build older than v0.1.1 loses this repo's worktree setup action until they update.
- `goat.json` keeps `$schema: https://t3.codes/schema/t3.json`, upstream's URL (D12).
- Kept by earlier decisions and unchanged here: legacy `T3CODE_*` env fallbacks (D5), the `t3code://` desktop origin (D13), mobile native module and bundle identifiers (ADR-0014), installed service identities (D16), migration names.
